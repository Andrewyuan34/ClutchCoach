# 教练组抉择、文字直播反馈、战术学习系统策划案

## 0. 目标

这份文档解决三个问题：

1. 指挥台如何从“战术按钮集合”变成“教练组临场会议”。
2. 文字直播如何承接抉择，让玩家看到平衡、代价和后续反馈。
3. 战术学习动画如何帮助玩家理解篮球，而不是把游戏变成考试。

当前项目已经有几个确定规则：

- 比赛进行中主视角是文字直播。
- 指挥台只在暂停 / 节间布置窗口出现。
- 指挥台内的战术和换人都是草稿，继续比赛时只提交最终方案。
- 继续后回到文字直播，由后续 3-5 回合验证这次布置。
- 所有关键行为都要支持 AI 可验证、可追溯、可 debug。

本案不推翻这些规则，而是在它们之上增加“教练组分工”和“战术学习层”。

### 0.1 主策划审稿结论

方向成立，但原案有一个危险倾向：

```text
它很容易从“主教练临场决策”变成“暂停会议阅读器”。
```

主策划视角下，必须先把体验压到一个最小闭环：

```text
一个场上问题
两个有冲突的助教意见
玩家拍板一个最终方案
文字直播验证一个收益或一个代价
```

这四步如果不好玩，更多助教、更多数据、更多动画都只是负担。

因此本案的优先级要重新校准：

1. 先证明“抉择有代价”好玩。
2. 再证明“直播反馈能验证代价”可信。
3. 最后才做“战术学习动画”的深度层。

战术学习动画是加深长期理解的系统，不是第一阶段救玩法的核心。

### 0.2 修订后的设计支柱

后续所有功能都要服从四条支柱。

| 支柱 | 含义 | 反例 |
| --- | --- | --- |
| 快速读局 | 3 秒内知道为什么暂停 | 一进指挥台看到四块长面板 |
| 冲突取舍 | 至少两个方案各有代价 | 一个绿色推荐按钮告诉答案 |
| 后果可见 | 3-5 回合内验证收益或代价 | 只写“调整开始见效” |
| 可选深度 | 想学的人能深入，不想学也能玩 | 强迫玩家看战术课 |

如果某个设计不能加强这四条之一，就应该删掉或后置。

### 0.3 必须先砍掉的过度设计

原案里有些内容可以保留为远期方向，但第一版不能一起上。

| 内容 | 主策划意见 | 原因 |
| --- | --- | --- |
| 四个助教每次都发言 | 降级 | 每次暂停最多 2 个助教意见，首席助教只做一句总结 |
| 战术学院主菜单 | 后置 | 当前核心问题在比赛内决策，不在外部教学入口 |
| 赛后复盘完整链路 | 后置 | 先把暂停后 3-5 回合反馈做可信 |
| 每个战术 4-6 帧动画 | 缩小 | MVP 先做 2 个战术验证表现形式 |
| 记录所有 adopted / ignored | 缩小 | MVP 只记录 adoptedAdviceId 和 acceptedCost |

第一版要像一把锋利的小刀，而不是一个完整教练组管理系统。

## 1. 先列游戏设计最佳实践

### 1.1 有意义的选择必须有代价

好选择不是“正确答案”，而是“我愿意承担这个代价”。

在本项目里，战术选择必须至少改变两个方向：

- 解决一个明显问题。
- 暴露或加重另一个风险。

示例：

| 选择 | 解决 | 代价 |
| --- | --- | --- |
| 包夹核心 | 降低对手球星连续得分 | 放空弱侧射手 |
| 强打内线 | 提高造犯规和篮下压力 | 怕护框和收缩 |
| 提速快攻 | 打乱对手站位 | 体力消耗和失误风险上升 |
| 换上射手 | 提高空间 | 防守和篮板下降 |
| 换上防守人 | 稳住对位 | 进攻处理球下降 |

如果助教只给“推荐 A”，玩家会变成执行系统答案。  
如果助教给“推荐 A，但代价是 B”，玩家才像主教练。

### 1.2 信息必须服务决策，不服务炫耀

指挥台不能把所有数据都摊开。

每条信息必须回答一个问题：

```text
我现在要不要叫暂停？
我暂停里优先解决什么？
我选择这个方案要放弃什么？
继续后我应该观察什么？
```

不能回答这四个问题的信息，默认不进第一屏。

### 1.3 玩家应该先感到问题，再得到工具

已有规则是正确的：

```text
文字直播暴露问题 -> 玩家叫暂停 -> 指挥台给工具 -> 直播验证结果
```

如果玩家没先看到问题，指挥台就会像后台菜单。  
如果玩家先被直播打痛，再看到助教分歧，决策会更有重量。

### 1.4 反馈要延迟但不能失联

篮球调整不是点完马上结算。

更好的反馈节奏是：

```text
提交最终布置
第 1 回合：执行迹象
第 2-3 回合：过程质量
第 3-5 回合：阶段结论
```

文字直播不能只说“调整成功”。它要能说：

- 成功在哪。
- 哪个代价开始显现。
- 之前哪个助教提醒被验证了。
- 下一步是坚持还是再调整。

### 1.5 不要用数值替代篮球语言

玩家不应该看到：

```text
spacing +12, rimProtect -8
```

玩家应该看到：

```text
空间被拉开了，但篮板保护变薄。
```

AI 可以读数值，玩家读篮球语言。

### 1.6 教学要按需出现

玩家不是所有时候都想上课。

战术学习应该分三层：

| 层级 | 出现方式 | 目标 |
| --- | --- | --- |
| 第一层 | 战术卡片短句 | 不学也能玩 |
| 第二层 | 助教解释 | 想赢得更稳时看 |
| 第三层 | 战术动画演示 | 想真正理解战术时深入 |

游戏不能要求玩家先看完教程才能玩。  
但玩家越懂战术，应该越能做出更好的判断。

### 1.7 失败也要有学习价值

失败反馈不能只惩罚玩家。

好的失败反馈应该让玩家知道：

```text
我错在判断问题？
错在战术选择？
错在阵容不支持？
错在对手反制？
还是选择合理但球员没投进？
```

这决定玩家会不会愿意再试一次。

### 1.8 角色化 UI 比报表 UI 更适合本项目

本项目的幻想是“我是主教练”，不是“我是数据分析后台管理员”。

所以信息来源应该角色化：

- 进攻助教说进攻。
- 防守助教说防守。
- 轮换助教说体力和阵容。
- 数据 / 球探助教说趋势和对手习惯。
- 主教练席位由玩家负责最终拍板。

角色化以后，同一组数据会更像篮球现场。

### 1.9 冲突建议比单一推荐更有戏

最有趣的临场不是“系统告诉我答案”，而是助教之间有合理分歧。

示例：

```text
进攻助教：对手收缩，应该拉开投三分。
轮换助教：现在最可靠的射手体力已经掉了。
防守助教：如果换上射手，弱侧篮板会丢。
玩家：我要不要牺牲篮板，先解决进攻断电？
```

这就是抉择平衡。

### 1.10 可验证性本身也是设计要求

每次决策必须能被机器追溯：

```text
哪条直播暴露了问题
哪个助教给了什么建议
玩家采纳了什么
玩家忽略了什么
最终布置是什么
后续反馈验证了什么
```

这不是只给测试用。  
它也能让后续 AI 帮玩家复盘：“你当时听了进攻助教，但忽略了轮换风险。”

## 2. NBA 教练组抽象成游戏系统

### 2.1 真实启发

NBA 比赛里，主教练通常不是一个人看完所有数据再计算最优解。

更像这样：

```text
场上发生问题
助教按各自职责快速压缩信息
主教练决定优先级
暂停里落成一套话术和战术
球员执行
教练组继续观察
```

游戏不需要完全写实，但可以借这个结构提升代入感。

### 2.2 游戏内教练组岗位

建议第一版先定义四个潜在助教角色，但不要保证每次都展示四个。

| 角色 | 关注 | 输出 | 典型提醒 |
| --- | --- | --- | --- |
| 首席助教 | 当前最大问题 | 一句话定性 | 他们连续打到禁区，先止血 |
| 进攻助教 | 我方怎么得分 | 战术建议 + 风险 | 打团队传导能破包夹，但需要第二持球点 |
| 防守助教 | 对手怎么得分 | 防守建议 + 风险 | 包夹核心能降温，但会放弱侧三分 |
| 轮换助教 | 谁该上谁该下 | 换人建议 + 代价 | 换上射手能拉开，但篮板会下降 |

后续可以加第五个：

| 角色 | 关注 | 输出 |
| --- | --- | --- |
| 球探 / 数据助教 | 对手倾向和历史样本 | 对手下一步可能反制 |

第一版不建议上太多角色，否则又会回到信息过密。

主策划修订：

```text
第一版可以有四个角色的数据源，但 UI 不应该每次显示四个人。
```

推荐显示规则：

| 情况 | 显示 |
| --- | --- |
| 普通暂停 | 首席助教总结 + 2 个最相关助教意见 |
| 新手助教模式 | 首席助教总结 + 1 个明确推荐 + 1 个代价提醒 |
| 关键时刻 | 首席助教总结 + 进攻/防守二选一，不再展开轮换长信息 |
| 玩家点“更多依据” | 才显示其他助教和证据 |

原因：

```text
教练组是信息来源，不是 UI 栏目数量。
```

玩家需要感受到“有人给我不同角度”，但不需要每次暂停都读完整会议纪要。

### 2.3 每个助教的输出格式

助教建议必须短，结构固定。

```js
{
  coachRole: "offense",
  title: "把球从强侧转出来",
  claim: "对手开始夹持球点，团队传导能制造弱侧空位",
  evidence: ["最近 2 回合都被迫停球", "弱侧射手被放空"],
  recommendation: { kind: "off", key: "motion" },
  cost: "如果第二持球点体力不足，传导会变成甩锅",
  watchFor: "看下一波是否出现弱侧空位三分",
  confidence: "medium"
}
```

玩家可见版压缩为：

```text
进攻助教：转移球能破夹击，但第二持球点体力是风险。
```

点开或开启助教提示后再看证据。

### 2.4 助教之间可以冲突

系统应该允许冲突，不要强行合成一个“最优推荐”。

冲突类型：

| 冲突 | 示例 |
| --- | --- |
| 进攻 vs 防守 | 上射手解决空间，但防守会被点名 |
| 防守 vs 轮换 | 需要夹击核心，但执行夹击的人体力不足 |
| 短期止血 vs 长期体力 | 主力继续打能稳住，但第四节会掉体力 |
| 球星信任 vs 系统执行 | 给球星硬解更稳心态，但对手已经准备包夹 |

这类冲突是指挥台的戏剧核心。

但冲突不能太多。

主策划约束：

- 每次暂停只呈现 1 个主要冲突。
- 冲突必须绑定当前最大问题。
- 冲突两边都必须可执行。
- 不允许出现三个以上互相打架的建议。

好的冲突：

```text
防守助教：收缩护框能止住禁区。
进攻助教：但收缩阵容会拖慢转换，进攻可能更堵。
```

坏的冲突：

```text
进攻助教建议 A，防守助教建议 B，轮换助教建议 C，数据助教建议 D。
```

坏冲突会让玩家觉得系统在甩锅，而不是帮助决策。

## 3. 新核心体验：教练组 huddle

### 3.1 原有指挥台的问题

当前指挥台已经比之前紧凑，但本质仍然偏“控件集合”：

```text
战术区
换人区
助教提示开关
最终方案
```

它能操作，但情绪还不够像暂停中的临场会议。

### 3.2 新定位

指挥台应该变成：

```text
暂停简报 + 教练组分歧 + 玩家拍板
```

玩家一进来先看到的不是所有战术，而是：

```text
当前最大问题是什么？
教练组有哪几个方向？
每个方向解决什么、牺牲什么？
我最终拍板哪套方案？
```

### 3.3 第一屏建议

移动端第一屏应该长这样：

```text
暂停布置  Q1 8:05      继续  18

最大问题
对手连续两回合打到禁区，护框压力正在上升。

教练组意见
[首席] 先止血：别让他们继续冲篮下
[进攻] 可以提速打乱他们站位，但会耗体力
[防守] 收缩护框最直接，代价是弱侧三分
[轮换] 文班体力还够，先别急着换

最终方案
进攻：提速快攻  防守：收缩护框  换人：暂无

[战术细调] [轮换] [看战术板]
```

这不是要多一堆卡片，而是把已有信息换成“教练组语言”。

主策划修订后的第一屏应更短：

```text
暂停布置  Q1 8:05      继续  18

最大问题
对手连续冲击禁区。

本次取舍
防守助教：收缩护框，能止住篮下；代价是底角会空。
进攻助教：保持提速，能打乱站位；代价是主力体力继续掉。

最终方案
防守：收缩护框  代价：底角三分

[采纳防守] [改战术] [看战术板]
```

关键变化：

- 不展示四个助教。
- 不同时展开进攻、防守、轮换三套操作。
- 把“本次取舍”放在战术按钮之前。
- 最终方案必须显示代价，而不只是显示战术名。

如果移动端第一屏放不下，优先删“看战术板”，不能删“最大问题 / 本次取舍 / 继续”。

### 3.4 玩家操作方式

每条助教意见可以有两种交互：

| 操作 | 效果 |
| --- | --- |
| 采纳 | 把对应战术 / 换人写入最终方案草稿 |
| 查看依据 | 展开证据、风险、战术动画入口 |

但默认不做“一键全采纳”。  
因为主教练要做取舍，而不是让助教自动接管。

还要避免另一个问题：

```text
如果每条助教意见都有“采纳”按钮，玩家会开始逐条点清单。
```

因此 MVP 只保留一个主操作：

```text
[采纳这个方向]
```

其他细调仍然在原有战术 / 换人区域完成。  
助教意见负责建立取舍，不负责替代整个指挥台。

## 4. 和文字直播结合

### 4.1 文字直播要给助教提供证据

直播行不能只是文本，它应该成为助教判断的证据来源。

流程：

```text
直播行产生 causeIds / contextId
系统聚合最近 3-5 个回合
生成 coachStaffBriefing
指挥台展示助教意见
玩家提交 commandCommit
后续直播验证 commandCommit
```

### 4.2 直播中的问题信号

问题信号不应该直接告诉标准答案。

推荐写法：

```text
尼克斯连续两个回合都被迫在边线停球，推进压力开始累积。
```

不推荐写法：

```text
建议立刻改打团队传导。
```

标准答案应该留给暂停后的助教提示。

### 4.3 暂停简报如何引用直播

进入指挥台时，`commandSession` 应该记录：

```js
{
  sourceLivecastIds: ["feed-0041", "feed-0042"],
  sourceContextIds: ["ctx-p-0037", "ctx-p-0038"],
  primaryProblem: "paint_pressure",
  staffBriefingId: "staff-0012"
}
```

玩家可见：

```text
最大问题：对手连续打到禁区。
来自：最近 2 回合。
```

AI 可见：

```text
这条最大问题来自哪些 livecastId / contextId。
```

### 4.4 继续后的文字直播反馈

提交最终布置后，文字直播先写一条摘要：

```text
最终布置：防守收缩护框，进攻继续提速；暂不换人。
```

随后 3-5 回合给反馈：

```text
第一回合执行迹象：
收缩护框立刻改变了站位，对手这次没有轻松进禁区。

第二回合代价出现：
但弱侧底角被放出来，对手已经开始找那一侧。

阶段结论：
这次布置止住了篮下，但外线风险正在变大，下一次要决定是否继续收缩。
```

这比单纯“调整开始兑现”更有系统感。

主策划修订：

反馈不要追求“完整解释”，要追求“玩家能把刚才的代价和眼前回合对上”。

MVP 只需要三类反馈：

| 类型 | 出现时机 | 作用 |
| --- | --- | --- |
| 执行迹象 | 暂停后第 1-2 回合 | 告诉玩家方案有没有真的执行出来 |
| 代价显现 | 相关风险首次出现 | 告诉玩家刚才接受的代价不是装饰 |
| 阶段结论 | 3-5 回合后 | 告诉玩家坚持还是再调整 |

暂时不要做太多“收益兑现 / 部分成功 / 失败复盘 / 对手反制”的分类。  
分类过多会导致文案像系统报告，不像直播。

第一版更应该像：

```text
你刚才选择收缩护框，这回合确实堵住了突破。
但代价也出现了：底角被放空，对手已经在找那一侧。
```

而不是：

```text
防守调整窗口 partial success，expectedCauseHits +1，negativeCauseHits +1。
```

### 4.5 反馈必须回应玩家的取舍

如果玩家采纳防守助教，忽略进攻助教，反馈可以写：

```text
你这次优先处理了护框，效果很快出现；但进攻端停球的问题还没解决。
```

如果玩家采纳轮换建议但忽略防守风险：

```text
换上射手后空间确实变好，但刚才防守篮板少了一只手，对手抢到了二次进攻。
```

这样玩家会记住“我做的是取舍”，不是单纯点按钮。

这里要加一条硬规则：

```text
没有在最终方案里记录的代价，直播不能事后拿来当反馈重点。
```

否则玩家会觉得系统在硬解释。

例：

```text
最终方案记录 acceptedCost = "corner_three"
```

后续可以写：

```text
刚才选择收缩后，底角风险第一次出现。
```

但不能突然写：

```text
你这次调整导致体力下降。
```

除非体力风险也在提交时被记录为 acceptedCost。

## 5. 抉择平衡系统

### 5.1 每次暂停只突出一个主问题

不要同时告诉玩家五个问题。

系统应该从最近回合选出一个主问题：

| 主问题 | 触发 |
| --- | --- |
| 禁区被打穿 | 对手 rimPressure 相关 cause 连续出现 |
| 推进被压 | turnover / press / ball_handler_mismatch 连续出现 |
| 空间不足 | badShot + lineup spacing 不足 |
| 体力风险 | tiredPlayers 增多，关键球员 stamina 低 |
| 球星被锁 | star_usage 高但效率下降 |
| 篮板失守 | 对手前场篮板或二次进攻增加 |

第一屏只讲主问题。  
其他问题放在助教分歧里。

### 5.2 每个方案有收益和代价

建议为每个战术建立“收益 / 代价 / 观察点”。

示例：

| 战术 | 收益 | 代价 | 观察点 |
| --- | --- | --- | --- |
| 团队传导 | 破解夹击，制造弱侧机会 | 需要持球和传球质量 | 是否出现弱侧空位 |
| 巨星单打 | 降低配合失误，给核心处理 | 怕包夹，消耗核心体力 | 核心是否能在包夹前出球 |
| 强打内线 | 制造犯规和篮下压力 | 怕护框，空间差会堵 | 是否能站上罚球线 |
| 外线火力 | 惩罚收缩 | 篮板和回防风险 | 是否有空位三分 |
| 收缩护框 | 降低禁区得分 | 放弱侧外线 | 对手是否转移到底角 |
| 包夹核心 | 降低球星输出 | 角色球员空位 | 对手是否找到第二点 |

### 5.3 教练组意见模板

每个助教都必须讲“收益 + 代价”。

```text
防守助教：收缩护框能止住冲击，但底角会空出来。
轮换助教：现在不换能保高度，但主力体力会继续掉。
进攻助教：提速能打乱他们联防，但失误风险会上升。
```

禁止只写：

```text
推荐收缩护框。
```

### 5.4 最终方案要记录采纳与忽略

`committedPlan` 不只记录最终战术，还应记录：

```js
{
  adoptedAdviceIds: ["advice-defense-001"],
  ignoredAdviceIds: ["advice-offense-001", "advice-lineup-001"],
  chosenTradeoffs: ["give_corner_three", "keep_starters_on_floor"],
  watchFor: ["corner_three_allowed", "starter_fatigue"]
}
```

这能支撑后续直播：

```text
刚才防守助教提醒过的底角风险出现了。
```

这种反馈会非常强。

主策划修订：

这个结构适合中后期，但 MVP 先不要记录太多字段。

第一版最小结构：

```js
{
  adoptedAdviceId: "advice-defense-001",
  acceptedCost: "corner_three",
  watchFor: ["paint_touch_denied", "corner_three_allowed"]
}
```

先证明这三个字段能带来明确反馈，再扩展到 ignoredAdviceIds / chosenTradeoffs。

原因：

```text
记录太多但反馈用不上，就是调试噪音。
```

主策划验收口径：

- 玩家能在最终方案里看到 `acceptedCost` 的玩家语言版本。
- 后续直播至少一次引用 `acceptedCost` 或 `watchFor`。
- AI 能证明反馈不是事后编的。

## 6. 战术学习动画系统

### 6.1 设计目标

战术动画不是普通教程，而是“暂停中的战术板”。

它应该让玩家理解：

```text
这个战术想制造什么机会？
它需要哪些球员能力？
它怕什么防守？
执行失败时通常哪里出问题？
```

### 6.2 不强迫学习

战术动画必须是可选深度。

默认玩家只看：

```text
团队传导：多传一次，破解夹击；需要第二持球点。
```

玩家点“看战术板”才进入动画。

这能避免新手被吓跑，同时给愿意研究的玩家成长空间。

### 6.3 动画内容结构

每个战术动画建议 4-6 个镜头。

以“团队传导”为例：

| 镜头 | 内容 | 文案 |
| --- | --- | --- |
| 1 | 持球点被夹击 | 对手想把球压在强侧 |
| 2 | 中路接应上提 | 第二持球点给出出球口 |
| 3 | 弱侧射手拉开 | 防守轮转被迫拉长 |
| 4 | 球转到底角 | 目标是弱侧空位三分 |
| 5 | 失败分支 | 如果没有第二持球点，传导会停住 |

动画不需要复杂 3D。  
第一版用半场 2D 战术板就够。

主策划修订：

第一版不要承诺每个战术 4-6 帧。

先做 2 个最能体现“取舍”的战术板：

| 战术 | 为什么先做 |
| --- | --- |
| 收缩护框 | 收益和代价最直观：堵禁区 vs 放底角 |
| 团队传导 | 能解释“为什么需要第二持球点”和“弱侧空位” |

每个战术板 MVP 只需要 3 帧：

| 帧 | 内容 |
| --- | --- |
| 问题 | 对手如何制造压力 |
| 解法 | 这个战术如何解决 |
| 代价 | 对手可能如何惩罚 |

实现修订：

当前版本把“三帧讲解”升级为“时间轴跑位”。
语义上仍保留问题 / 解法 / 代价这些节点，但球员、篮球、箭头、风险区域会随 `playheadMs` 连续移动。玩家可以点上一步 / 下一步跳到节点，也可以播放跑位或拖动进度条观察细节。

如果这 2 个战术板不能让玩家更理解暂停选择，就不要继续扩到 6 个。

### 6.4 动画触发位置

建议三个入口：

| 入口 | 使用场景 | 是否暂停比赛 |
| --- | --- | --- |
| 指挥台战术卡片 | 临场想快速理解 | 已经暂停 |
| 赛后复盘 | 看刚才为什么成败 | 不影响比赛 |
| 主菜单战术学院 | 纯学习 | 不影响比赛 |

比赛进行中不弹动画，避免打断文字直播。

### 6.5 学习如何影响游戏

不建议做硬门槛：

```text
看过教程才能解锁战术
```

更建议做软收益：

```text
看过战术板后，玩家更懂什么时候用。
助教提示可以更少、更克制。
复盘里可以指出玩家是否用在了正确场景。
```

可以有轻量记录：

```js
learnedTactics: {
  motion: { watched: true, lastWatchedAt: "..." },
  paint: { watched: false }
}
```

但不要给数值加成。  
真正的收益应该是玩家理解提升。

主策划补充：

战术学习不能变成“玩家看了动画，所以系统给奖励”。  
它应该变成“玩家看了动画，所以更容易读懂直播”。

可接受的学习收益：

- 战术卡片文案从极短版升级为更懂球的观察点。
- 赛后复盘能标出“你这次用到了收缩护框的代价点”。
- 助教提示可以少讲答案，多讲观察目标。

不可接受的学习收益：

- 看过动画后战术数值增强。
- 没看动画就锁定战术。
- 把战术学习做成每日任务。

本项目的学习动机应该来自“我终于看懂刚才发生了什么”，不是来自外部奖励。

### 6.6 动画和文字直播的连接

动画里的观察点要和直播反馈使用同一套词。

示例：

动画教玩家看：

```text
弱侧是否出现空位
持球点是否能提前出球
```

直播反馈也写：

```text
这回合球终于提前从强侧出来，弱侧出现了空位。
```

这样玩家会把学习内容带回比赛。

### 6.7 战术动画数据结构

建议新建 `TACTIC_LESSONS`：

```js
{
  motion: {
    title: "团队传导",
    intent: "破解夹击和收缩，制造弱侧空位",
    needs: ["secondary_handler", "spacing", "passing"],
    counters: ["double", "press", "paint"],
    risks: ["turnover", "late_clock"],
    watchFor: ["weakside_open", "early_release"],
    frames: [
      {
        label: "持球点被夹",
        players: [{ id: "handler", x: 32, y: 50 }],
        defense: [{ id: "trap1", x: 35, y: 48 }],
        arrows: [],
        text: "对手把球压在强侧。"
      }
    ]
  }
}
```

AI 可以验证：

- 每个战术有 intent。
- 每个战术有 needs / risks / watchFor。
- 每个动画至少 4 帧。
- 直播反馈中的 watchFor 能追溯到 lesson。

## 8. 指挥台 UI 方案

### 8.1 默认态

默认态不显示“推荐答案”，显示“教练组意见”。

```text
最大问题
对手连续冲击禁区

教练组
首席：先止住禁区
防守：收缩护框，代价是底角
进攻：保持提速，代价是体力

最终方案

默认态不应该把所有助教都摊开。

### 8.2 助教提示开启

开启后，每条意见展开证据和按钮：

[采纳防守] [看战术板]
```

### 8.3 玩家拍板区

最终方案区应一直可见。

它要显示：

```text

你接受了什么代价

```

```text

```

### 8.4 战术学习入口

战术卡片上放一个轻入口：

```text

```

不要叫“教程”。  
“战术板”更符合教练语境。

## 9. 文字直播反馈方案

### 9.1 反馈分类

MVP 只保留三类反馈。

| 类型 | 触发 | 文案目标 |
| --- | --- | --- |
| 执行迹象 | 提交后 1-2 回合 | 说明方案是否被执行出来 |
| 代价显现 | acceptedCost 首次命中 | 告诉玩家牺牲开始出现 |
| 阶段结论 | 3-5 回合后 | 告诉玩家坚持还是再调整 |

后续再扩展：

| 类型 | 后置原因 |
| --- | --- |
| 收益兑现 | 容易和执行迹象重复 |
| 部分成功 | 需要更稳定的判定标准 |
| 失败复盘 | 文案要求高，容易像事后找理由 |
| 对手反制 | 要先把玩家自身反馈做可信 |

### 9.2 示例链路

暂停前：

```text
布伦森又一次被夹在边线，尼克斯推进开始变慢。
```

指挥台：

```text
进攻助教：团队传导能给弱侧出球口，但需要第二持球点。
轮换助教：麦克布莱德体力够，可以补这个点，但进攻火力会降一点。
```

最终布置：

```text
最终布置：进攻改团队传导，麦克布莱德上来分担持球。
```

反馈：

```text
暂停回来第一攻，球没有再被压死在强侧，弱侧终于接到了转移球。
```

再反馈：

```text
但麦克布莱德上来后终结威胁不够，对手开始敢放他一步。
```

阶段结论：

```text
这次调整解决了推进问题，但没有完全解决终结问题。下一次要决定是继续保组织，还是换回火力。
```

### 9.3 反馈节奏限制

为了避免刷屏：

- 最终布置只有 1 条。
- 3-5 回合内最多 2 条解释反馈。
- 每条反馈只讲一个原因。
- 如果已经出现代价反馈，本窗口不再重复同一代价。

## 11. 自我拷打：这套方案可能哪里不好

### 11.1 风险：信息又变多了

问题：

教练组角色听起来有趣，但每个助教都说话，可能比现在更吵。

约束：

- 第一屏最多 4 条助教意见。
- 每条默认 1 行。
- 证据和动画必须按需展开。
- 同一角色每次只说一个重点。

### 11.2 风险：玩家以为助教意见就是答案

问题：

如果 UI 写“推荐”，玩家仍然会照抄。

约束：

- 默认叫“意见”，不叫“推荐”。
- 每条意见必须带代价。
- 最终方案区要显示“你接受的代价”。

### 11.3 风险：反馈显得系统在事后找理由

问题：

如果提交时没有记录 watchFor，后续反馈会像硬编。

约束：

- 提交时必须记录 `watchFor` 和 `acceptedCost`。
- 后续反馈只能引用提交时记录过的收益 / 代价。
- AI 断言检查反馈是否引用 committedPlan。

### 11.4 风险：战术动画成本太高

问题：

每个战术都做动画会增加资源成本。

约束：

- 第一版只做 2 个核心战术。
- 用 2D 战术板，不做复杂人物动画。
- 每个战术 3 帧，复用球员圆点、箭头、区域高亮。
- 动画数据结构驱动，避免每个战术手写 DOM。

### 11.5 风险：懂战术的人更强，不懂的人被劝退

问题：

如果战术理解成为硬门槛，新手会压力大。

约束：

- 基础战术卡片必须足够可玩。
- 助教提示能兜底。
- 战术动画提供成长，不提供数值加成。
- 失败反馈要告诉玩家下一次看什么。

### 11.6 风险：篮球真实性和游戏清晰度冲突

问题：

真实 NBA 很复杂，但游戏需要清楚。

约束：

- 每次暂停只突出一个主问题。
- 每条反馈只讲一个原因。
- 每个战术最多绑定 2 个主要收益和 2 个主要代价。
- 不做完整真实战术树，先做可读的教练决策模型。

### 11.7 风险：每次暂停都长得一样

问题：

如果每次都是“最大问题 + 两条意见 + 最终方案”，玩家可能很快看穿模板。

约束：

- 主问题类型要影响节奏：体力问题偏轮换，禁区问题偏防守，推进问题偏进攻。
- 不是每次都必须出现冲突；领先时可以是“保守 vs 扩大优势”，落后时可以是“追分 vs 控失误”。
- 关键时刻要减少信息，只保留最尖锐的二选一。

### 11.8 风险：玩家没有足够理由相信助教

问题：

如果助教意见只是一句判断，玩家会觉得它是系统随机生成。

约束：

- 每条意见至少引用一个可感知证据，例如“最近两回合”“刚才那次底角”“文班体力”。
- 证据必须来自 livecastId / contextId。
- 证据不要变成数据表，默认仍是篮球语言。

### 11.9 风险：主教练感被助教抢走

问题：

助教越像系统答案，玩家越不像主教练。

约束：

- UI 文案避免“应该”“必须”“最佳”。
- 使用“如果你要解决 X，可以接受 Y 的代价”。
- 最终方案区用“你选择”而不是“系统推荐”。
- 复盘优先评价玩家取舍，而不是评价玩家是否听话。

## 12. 主策划上线前拷问

在进入实现前，团队必须能回答这些问题。

### 12.1 30 秒体验是否成立

```text
玩家叫暂停后，30 秒内能不能完成：
看懂问题 -> 理解取舍 -> 拍板 -> 继续比赛
```

如果不能，说明信息还是太多。

### 12.2 不懂篮球的玩家能不能玩

```text
玩家不知道“弱侧”“夹击”“沉退”，是否仍能通过短句做选择？
```

如果不能，战术语言需要再翻译一层。

### 12.3 懂篮球的玩家会不会觉得假

```text
战术收益和代价是否符合基本篮球直觉？
```

如果不符合，宁愿少做战术，也不要做错战术。

### 12.4 反馈是否真的来自选择

```text
直播反馈能不能追溯到 acceptedCost / watchFor？
```

如果不能，这套系统会变成包装过的随机文案。

### 12.5 这个系统有没有让暂停更值钱

```text
玩家是否因为“想进入教练组 huddle”而更认真考虑叫暂停时机？
```

如果暂停还是随手点，说明系统没有改变核心节奏。

### 12.6 成功指标

第一版上线后先看这些指标：

| 指标 | 目标 |
| --- | --- |
| 玩家进入指挥台后的平均停留 | 8-25 秒，太短说明没看，太长说明太复杂 |
| 助教提示开启率 | 新手高、熟练后下降 |
| 暂停后 5 回合内反馈可见率 | 接近 100% |
| 连续乱点战术比例 | 下降，说明玩家更像在拍板 |
| 玩家复述能力 | 玩家能说出“我刚才牺牲了什么” |

最后一条最重要。  
如果玩家说不出自己刚才接受了什么代价，系统就还没做成。

## 13. 分阶段落地建议

### Phase 0：纸面原型和文本验证

目标：

```text
先不写复杂系统，用固定场景验证“两个冲突意见”是否好玩。
```

范围：

- 选 3 个典型问题：禁区被打穿、推进被压、空间不足。
- 每个问题写 2 条冲突助教意见。
- 每条意见写收益、代价、观察点。
- 人工跑 5 次暂停流程，看玩家是否能做出取舍。

验收：

```text
玩家能在不看数值的情况下说出自己选了什么、牺牲了什么。
```

### Phase 1：教练组文字层

目标：

```text
不用改大 UI，先让指挥台有教练组意见。
```

范围：

- 新增 `CoachStaffBriefing` 数据。
- 指挥台最大问题改成 `primaryProblem`。
- 助教提示开启后展示 1-2 条角色化意见。
- 每条意见有收益、代价、观察点。
- 最终方案记录 `adoptedAdviceId` / `acceptedCost` / `watchFor`。

验收：

```text
玩家能看到不同助教的不同立场。
每条意见都有代价。
继续后直播能回应本次 acceptedCost 或 watchFor。
```

### Phase 2：反馈升级

目标：

```text
让文字直播反馈具体回应取舍。
```

范围：

- `AdjustmentWindow` 增加 `watchFor` 和 `acceptedCost`。
- 反馈文案先只做执行迹象、代价显现、阶段结论。
- 限制 3-5 回合内最多 2 条解释反馈。

验收：

```text
直播能说清楚：解决了什么，代价是什么，下一步看什么。
```

### Phase 3：战术板动画 MVP

目标：

```text
用 2 个战术证明动画能帮助玩家理解取舍。
```

范围：

- 新增 2D 半场战术板组件。
- 新增 `TACTIC_LESSONS` 数据。
- 先做 `收缩护框` 和 `团队传导`。
- 每个战术用时间轴表达跑位，保留问题、解法、代价三个以上的语义节点。
- 指挥台战术卡片加入“看战术板”入口。

首批战术：

```text
收缩护框
团队传导
```

验收：

```text
玩家能从战术板看到意图、需求、风险、观察点，并能看见球员和球按时间轴移动。
动画不阻塞正常比赛。
看过动画后，玩家能更准确理解对应直播反馈。
```

### Phase 4：赛后复盘和学习闭环

目标：

```text
让战术学习和比赛表现互相强化。
```

范围：

- 赛后展示 1-2 个关键暂停。
- 标记玩家当时采纳了哪些助教意见。
- 展示相关战术板入口。
- 给出“下次观察点”。

验收：

```text
玩家知道自己不是输在随机，而是某个取舍被验证或惩罚。
```

当前落地状态：

- 已在终场卡加入“教练组复盘”，最多展示 2 个关键指挥台会话。
- 每条复盘追溯到 `commandSessionId`、`coachActionId`、`adjustmentId`、`acceptedCost`、`adoptedAdviceId`。
- 复盘文案展示当时的问题、玩家采纳的助教方向、接受的代价、后续反馈、下次观察点。
- 如果该选择关联 `TACTIC_LESSONS`，终场复盘会提供“看战术板”入口。
- 直播反馈会回填到对应指挥台历史，AI 可以从终场复盘反查到当时的直播行和战术调整窗口。

## 15. 最终判断

这个方向更有意思。

原因不是“多了助教”和“多了动画”，而是它把玩家身份变清楚了：

```text
助教提供不同视角。
玩家做主教练取舍。
文字直播验证取舍。
战术板帮助玩家理解下一次怎么取舍。
```

如果只做助教推荐，它会变成自动答案。  
如果只做战术动画，它会变成教程。  
如果只做直播反馈，它会变成事后解释。

三者合起来才是系统：

```text
看到问题 -> 听到分歧 -> 做出取舍 -> 看见后果 -> 学会下一次
```

但主策划结论要更克制：

```text
先做一个小而尖的教练组取舍闭环。
不要先做完整教练组。
不要先做完整战术学院。
不要先做复杂赛后复盘。
```

第一版只要做到：

```text
玩家因为文字直播看到问题。
暂停后看到两个有代价的方向。
玩家拍板一个方向。
直播验证这个方向的收益或代价。
```

这就已经比当前指挥台更强。

等这条闭环被证明好玩，再扩展更多助教、更多动画、更多复盘。
