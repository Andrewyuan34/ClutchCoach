# 指挥台 UI 信息密度优化详细方案

## 1. 一句话结论

当前指挥台的问题不是信息不该存在，而是信息在同一层级同时展开。

玩家确实需要看到暂停原因、最近回合、战术关系、阵容状态、换人建议、助教提示和继续比赛按钮，但这些信息不应该全部纵向堆开。

新的方向是：

```text
一屏完成主要决策
细节按需展开
操作始终在手边
AI 仍然能验证完整信息链路
```

指挥台要从“信息报表页”变成“暂停布置板”。

## 2. 当前体验问题

### 2.1 信息都对，但同时出现

现在指挥台进入后，玩家会连续看到：

```text
暂停指挥台标题
暂停原因
最近回合
倒计时
球队气势
助教提示按钮
助教建议
读局面板
对手战术
我方进攻战术 6 个按钮
我方防守战术 6 个按钮
换人区
场上五人
替补席
继续比赛按钮
```

这些信息单独看都有价值，但全部摊开后会产生几个问题：

- 玩家第一眼不知道该先看哪里。
- 战术和换人两个核心操作被大量说明挤下去。
- 页面纵向过长，移动端需要滑很久。
- 助教建议、读局面板、战术按钮说明之间有重复。
- 指挥台看起来更像调试面板，而不是教练暂停时的战术板。

### 2.2 视觉权重没有区分

目前很多模块都在争夺注意力：

- 暂停原因想要解释为什么进来。
- 倒计时想要制造紧迫感。
- 气势条想要呈现局势。
- 助教建议想要给答案。
- 读局面板想要给分析。
- 战术按钮想要可操作。
- 换人名单想要可操作。

如果这些模块视觉权重接近，玩家会觉得“全都重要”，最后反而抓不到重点。

指挥台应该先给玩家一个明确路径：

```text
先确认问题
再决定主方向
最后细调战术或换人
```

### 2.3 纵向滑动破坏暂停感

暂停是一段短时间决策。

玩家进入指挥台后，如果要先向下滑很多才能看到完整操作，就会损失暂停的紧张和爽感。

理想体验应该是：

```text
进入指挥台
第一屏就知道问题
第一屏就能做主要选择
第一屏就能继续比赛
```

详细信息可以存在，但不应该挡住主要流程。

### 2.4 复杂度对新手和老玩家都不友好

新手看到太多信息，会不知道哪些是必须处理的。

老玩家看到太多长文案，会觉得操作效率低。

所以不能简单地“删信息”，也不能继续“堆信息”。

需要做信息架构分层：

```text
新手默认看到结论和建议
老玩家可以展开看细节
AI 可以读取完整结构
```

## 3. 设计目标

### 3.1 玩家目标

玩家进入指挥台后，应该在 3 秒内回答：

```text
我为什么叫暂停？
现在最大的场上问题是什么？
我应该优先改战术、换人，还是继续观察？
我当前最终方案是什么？
```

### 3.2 UI 目标

新的指挥台需要做到：

- 第一屏完成核心决策。
- 继续比赛按钮始终容易触达。
- 战术和换人不再同时完整展开。
- 长文案收敛为摘要。
- 细节按需展开，不丢失深度。
- 移动端不需要长距离滑动才能操作。
- 助教提示不再额外制造一大块信息噪音。

### 3.3 系统目标

优化 UI 后，不能破坏已有系统规则：

- 指挥台只在暂停 / 节间窗口出现。
- 战术仍然是暂停内草稿，继续比赛时提交最终方案。
- 换人仍然归属于同一个 commandSession。
- AI 仍然能追踪暂停原因、最近回合、最终战术、换人和后续反馈。
- 新手助教模式仍然可以高亮引导。

## 4. 新的信息架构

### 4.1 总体结构

推荐把指挥台改成四层：

```text
固定顶部层：比分、时间、倒计时、继续比赛
简报层：暂停原因、最大风险、最近 2 回合
决策层：战术 / 换人 / 助教 三个模式
摘要层：当前最终方案、提交状态
```

视觉上不要再像一串长表单，而是像一个临场工作台。

### 4.2 第一屏结构

移动端第一屏建议如下：

```text
┌────────────────────────────┐
│ NY 47  SA 51   Q2 7:42     │
│ 暂停布置  18s    继续比赛  │
├────────────────────────────┤
│ 暂停原因                   │
│ 对手连续冲击禁区，我方护框吃紧 │
│ 风险：再放任会被打出一波流       │
│ 最近：文班空接 / 我方三分偏出     │
├────────────────────────────┤
│ [战术] [换人] [助教]        │
├────────────────────────────┤
│ 当前进攻：团队传导          │
│ 建议调整：外线火力          │
│ 备选方案：巨星单打          │
│ 更多战术                   │
├────────────────────────────┤
│ 最终方案：外线火力 + 收缩护框 │
└────────────────────────────┘
```

第一屏只保留：

- 为什么暂停。
- 当前最大风险。
- 当前操作模式。
- 主要候选操作。
- 最终方案摘要。
- 继续比赛入口。

### 4.3 桌面端结构

桌面端可以更充分，但仍然要分区。

推荐双栏：

```text
┌──────────────────────────────────────────┐
│ 比分 / 时间 / 倒计时 / 继续比赛          │
├──────────────────────────────────────────┤
│ 左：暂停简报              右：最终方案摘要 │
├──────────────────────────────────────────┤
│ 主决策区：战术 / 换人 / 助教             │
└──────────────────────────────────────────┘
```

桌面端可以同时展示“简报”和“方案摘要”，但战术、换人仍然不要全部展开。

## 5. 模块重设计

## 5.1 固定顶部层

### 目标

让玩家随时知道：

- 当前比分。
- 当前时间。
- 这是不是暂停布置。
- 还剩多少布置时间。
- 如何继续比赛。

### 推荐内容

```text
暂停布置
NY 47 - 51 SA · Q2 7:42
18s
[继续比赛]
```

### 行为规则

- 顶部在指挥台内 sticky。
- 倒计时始终可见。
- 继续比赛按钮始终可见。
- 如果玩家滑到下方，仍然能直接继续。
- 倒计时小于 5 秒时只强化倒计时，不弹大提示。

### 为什么要 sticky

现在玩家要滑到底部或找按钮，暂停节奏会断。

sticky 顶部可以让玩家放心探索信息，不担心找不到出口。

## 5.2 暂停简报层

### 目标

把原来的暂停原因、最近回合、局势和风险压缩成一个高信息密度但不吵的简报。

### 推荐结构

```text
暂停原因
对手连续冲击禁区，我方护框压力上升

最大风险
如果继续人盯人，弱侧协防会被拉开

最近回合
1. 文班亚马空接得手
2. 阿奴诺比三分偏出
```

### 默认显示

默认只显示：

- 一句话原因。
- 一条最大风险。
- 最近 2 回合。

### 可展开内容

点击“展开复盘”后显示：

- 最近 4 回合。
- 对应 possessionId / contextId。
- 关键原因标签。
- 相关战术触发原因。

### 为什么最近回合只显示 2 条

暂停进来时，玩家不需要重读完整直播。

他只需要被提醒：

```text
刚才到底发生了什么？
```

2 条足够唤起记忆，4 条适合复盘，更多应该留在文字直播本身。

## 5.3 读局面板压缩

### 当前问题

现在读局面板有五行：

```text
局势
战术
阵容
风险
建议
```

这五行都对，但视觉上像分析表格，容易显得重。

### 新方案

默认压缩为三条：

```text
局势：对手正在打禁区压力
风险：我方护框偏弱
建议：优先收缩护框，或换上护框球员
```

### 信息迁移

原来的五行不删除，而是迁移：

| 旧信息 | 新位置 |
| --- | --- |
| 局势 | 暂停简报主句 |
| 战术 | 战术卡片内 |
| 阵容 | 换人卡片内 |
| 风险 | 暂停简报风险 |
| 建议 | 当前模式的推荐候选 |

这样信息仍然完整，但不会集中堆在顶部。

## 5.4 战术区重设计

### 当前问题

进攻 6 个按钮、防守 6 个按钮同时展开，信息密度太高。

玩家第一次进入会看到 12 个战术选择，并且每个都有名称、图标、说明、推荐状态。

这适合高级玩家精调，不适合作为默认首屏。

### 新结构

战术区默认只显示：

```text
当前方案
推荐方案
备选方案
更多方案
```

进攻和防守分段展示，不一次把 12 个全部铺开。

### 示例

```text
进攻战术

当前：团队传导
适合：破包夹、多点传导

推荐：外线火力
原因：对手收缩禁区，弱侧三分有空间

备选：巨星单打
原因：核心手感好时可硬解

[更多进攻战术]
```

防守同理：

```text
防守战术

当前：人盯人
推荐：收缩护框
备选：包夹核心
[更多防守战术]
```

### 更多方案展开规则

点击“更多进攻战术”后再展示全部 6 个进攻方案。

展开后的方案仍然要分组：

```text
稳妥
- 均衡进攻
- 团队传导

针对
- 外线火力
- 强打内线

冒险
- 提速快攻
- 巨星单打
```

这样比平铺 6 个按钮更容易读。

### 战术卡片信息

每个战术卡片建议只显示三层：

```text
战术名
一句话作用
适配 / 风险标签
```

示例：

```text
外线火力
拉开空间，惩罚收缩
适配：空间强  风险：篮板弱
```

不要默认显示长解释。

助教提示打开后，再出现更完整的“为什么推荐”。

## 5.5 换人区重设计

### 当前问题

换人区默认展示场上五人和替补席，信息真实但占空间巨大。

玩家暂停进来时，不一定想进行完整轮换管理。

很多时候他只想知道：

```text
谁累了？
谁状态差？
为了当前战术，应该换谁？
```

### 新结构

换人区默认显示“轮换建议”，完整名单折叠。

```text
轮换建议

布伦森体力 42，建议休息 2 分钟
可换上：阿尔瓦拉多
作用：补体力和持球压迫

唐斯护框压力大
可换上：米切尔-罗宾逊
作用：补禁区保护

[查看完整阵容]
```

### 完整阵容展开规则

点击“查看完整阵容”后，展示：

- 场上五人。
- 替补席。
- 体力。
- 状态。
- 关键标签。

但展开后仍然要保持紧凑：

```text
PG 布伦森  体力 42  手感热
SG 布里奇斯 体力 76  防守稳
```

不要默认把每个球员卡做得很高。

### 换人和战术联动

换人推荐必须读当前战术草稿。

例如：

```text
你选择外线火力
当前场上空间点不足
推荐上沙梅特
```

```text
你选择收缩护框
当前内线护框偏弱
推荐上罗宾逊
```

这会让战术和换人形成系统感，而不是两个独立按钮区。

## 5.6 助教提示重设计

### 当前问题

助教提示现在会额外展开一块建议区。

它提供的信息有价值，但也增加了一个大模块，使页面更长。

### 新方向

助教不再作为单独大面板，而是变成“解释层”。

关闭时：

```text
只显示当前、备选、更多入口
```

打开时：

```text
战术卡片显示推荐原因
换人建议显示适配理由
风险区显示更完整解释
```

也就是说：

```text
助教提示 = 给现有模块加解释
不是新增一个大模块
```

### 示例

关闭助教：

```text
推荐：外线火力
```

打开助教：

```text
推荐：外线火力
原因：对手收缩护框，弱侧射手空位概率提高
风险：如果前场篮板丢失，会被对手推转换
```

### 新手模式规则

新手助教模式下可以默认打开解释层。

普通模式下仍然默认关闭。

这和之前“非新手不默认推荐”的规则一致。

## 5.7 最终方案摘要

### 目标

玩家暂停中可能做多个操作，底部需要随时告诉他最终会提交什么。

### 推荐显示

```text
最终方案
进攻：外线火力
防守：收缩护框
换人：罗宾逊上，唐斯下
```

### 行为规则

- 摘要 sticky 在底部，或者放在顶部右侧。
- 每次草稿变动后即时更新。
- 如果和暂停前没有变化，显示“未调整”。
- 点击继续比赛时，提交这个摘要里的最终方案。

### 为什么需要摘要

这能解决玩家暂停期间反复点战术后的不确定感：

```text
我刚才点过很多个，最终到底是哪一个？
```

摘要直接给答案，也方便 AI 验证。

## 6. 推荐页面形态

## 6.1 移动端首屏

移动端高度最紧张，推荐优先保证一屏可操作。

```text
┌──────────────────────────────┐
│ NY 47 - 51 SA     Q2 7:42     │
│ 暂停布置 18s      继续比赛     │
├──────────────────────────────┤
│ 对手连续冲击禁区               │
│ 风险：护框压力上升             │
│ 最近：文班空接 / 我方三分偏出   │
├──────────────────────────────┤
│ [战术] [换人] [助教]           │
├──────────────────────────────┤
│ 进攻：当前 团队传导             │
│ 推荐 外线火力                  │
│ 备选 巨星单打                  │
│                                │
│ 防守：当前 人盯人               │
│ 推荐 收缩护框                  │
├──────────────────────────────┤
│ 最终：外线火力 + 收缩护框       │
└──────────────────────────────┘
```

移动端默认不显示：

- 完整读局五行。
- 全部 12 个战术。
- 完整替补席。
- 长助教文案。
- 大面积气势说明。

这些进入展开层。

## 6.2 桌面端首屏

桌面端可以使用左右布局。

```text
┌────────────────────────────────────────────┐
│ 暂停布置 · Q2 7:42 · 18s      [继续比赛]   │
├──────────────────────┬─────────────────────┤
│ 暂停简报             │ 最终方案             │
│ 对手冲击禁区         │ 进攻：外线火力       │
│ 风险：护框吃紧       │ 防守：收缩护框       │
│ 最近 2 回合          │ 换人：暂无           │
├──────────────────────┴─────────────────────┤
│ [战术] [换人] [助教]                         │
│ 主决策区                                     │
└────────────────────────────────────────────┘
```

桌面端可以显示更多信息，但仍然不建议默认铺开完整战术和完整名单。

## 7. 交互规则

### 7.1 默认进入状态

玩家叫暂停进入指挥台时：

```text
默认打开：战术模式
默认显示：当前方案、备选方案、更多入口
默认隐藏：完整战术列表、完整阵容名单
默认隐藏：推荐标签、推荐摘要、一键推荐换人
```

为什么默认是战术模式：

- 战术是玩家最核心的临场决策。
- 换人依赖战术意图。
- 助教是解释层，不应该抢主入口。

### 7.2 模式切换

三个主模式：

```text
战术
换人
助教
```

也可以设计为：

```text
战术 / 换人
助教开关
```

更推荐第二种：

```text
[战术] [换人]        助教提示开关
```

因为助教不是独立操作，它是对战术和换人的解释。

### 7.3 更多展开

所有“更多”都应遵守同一个规则：

```text
默认只显示最有用的 2-3 项
展开后显示完整列表
展开状态可收回
展开不会改变最终方案
```

### 7.4 点击战术

点击备选战术后：

- 立刻更新当前草稿。
- 更新最终方案摘要。
- 更新换人建议。
- 不立即生成正式直播。
- 不关闭指挥台。

### 7.5 点击换人

默认换人区先显示轮换检查，不直接给一键推荐换人：

```text
体力关注：某球员 68体力
替补最足：某球员 94
```

当助教提示打开后，推荐换人才可以一键完成。

执行推荐换人后，推荐区不应继续刷新下一条推荐，而应切换为确认态：

```text
已加入最终方案
某球员上，某球员下
继续比赛后按这套轮换执行
```

这样玩家会明确知道操作已经生效，后续更多换人应该通过完整阵容展开完成。

高级玩家可以展开完整名单进行手动换人。

### 7.6 继续比赛

继续比赛按钮点击后：

- 提交最终方案摘要。
- 提交换人草稿。
- 关闭指挥台。
- 回到文字直播。
- 后续直播反馈本次调整效果。

## 11. 分阶段执行建议

### Phase 1：信息分层，不改业务逻辑

目标：

```text
先把页面变短，让第一屏能决策。
```

改动：

- 新增 sticky 顶部。
- 简报压缩。
- 最终方案摘要。
- 战术区默认只显示当前 / 备选 / 更多。
- 完整战术列表放进“更多”。
- 换人区默认只显示轮换检查，助教打开后显示推荐轮换。

不改：

- 战术计算。
- 换人规则。
- commandSession。
- AI trace。

验收：

```text
手机首屏能看到原因、主要战术、继续比赛。
默认不显示完整 12 个战术按钮。
默认不显示完整替补席。
```

### Phase 2：助教解释层

目标：

```text
助教不再额外撑开页面。
```

改动：

- 助教开关仍存在。
- 开启后给战术卡、换人卡、风险区增加解释。
- 取消默认大块 `coach-advice` 的视觉占位。

验收：

```text
关闭助教时页面仍然完整可玩。
开启助教时解释更丰富，但页面不明显变长。
```

### Phase 3：完整阵容和高级战术展开

目标：

```text
高级玩家仍然可以细调。
```

改动：

- 更多战术展开。
- 完整阵容展开。
- 展开状态进入 AI snapshot。

验收：

```text
默认紧凑，展开完整。
展开不提交战术。
只有点击具体战术或换人才改变草稿。
```

### Phase 4：AI 验证扩展

目标：

```text
AI 可以验证这不是把信息删了，而是分层了。
```

改动：

- 新增 commandUi snapshot。
- 新增 compact / expanded 断言。
- 新增 finalPlan 断言。
- 新增 command.commit snapshot，记录继续比赛后的最终布置摘要。
- 新增 commit summary / no draft spam 断言，确保直播只播最终方案，不播暂停内每一次试点。
- 更新 docs/ai-verification.md。

验收：

```text
AI 能证明默认 compact。
AI 能证明 final plan 和点击结果一致。
AI 能证明继续比赛提交最终方案。
AI 能证明最终方案有 coachActionId / adjustmentId / livecastId，后续反馈可以追溯回这次指挥台。
```

## 12. 视觉设计原则

### 12.1 降低卡片数量

不要把每个信息块都做成大卡片。

建议：

- 顶部是工具栏。
- 简报是一个紧凑面板。
- 决策区是主内容。
- 战术和换人项是小卡片。

避免：

```text
卡片套卡片
每行都是大圆角块
所有模块都有重边框
```

### 12.2 缩短文案

默认文案尽量一句话。

例如：

```text
对手连续冲击禁区，护框压力上升。
```

不要默认写：

```text
对手在过去几个回合中持续利用身体优势冲击篮下，我方禁区保护和弱侧协防正在承受较大压力，因此建议考虑收缩防线或调整内线轮换。
```

长解释放进助教展开层。

### 12.3 用标签替代长句

示例：

```text
适配：空间强
风险：篮板弱
针对：收缩防守
```

比长段落更适合暂停决策。

### 12.4 操作按钮要少而明确

默认一屏内不应出现超过 5 个主要操作按钮。

推荐：

- 推荐进攻。
- 备选进攻。
- 推荐防守。
- 换人建议。
- 继续比赛。

完整列表放在“更多”。

## 13. 风险和取舍

### 13.1 风险：玩家觉得战术变少了

解决：

```text
保留“更多战术”入口。
展开后仍然完整显示全部方案。
```

默认减少的是视觉噪音，不是系统深度。

### 13.2 风险：AI 验证读不到折叠内容

解决：

```text
折叠信息仍然进 snapshot。
隐藏 DOM 可以有 data 属性。
AI 不依赖肉眼可见文本完成追踪。
```

### 13.3 风险：新手助教需要更强提示

解决：

```text
新手模式默认打开助教解释层。
普通模式默认关闭。
```

### 13.4 风险：sticky 顶部占用移动端空间

解决：

```text
顶部高度控制在 48-56px。
比分和倒计时合并显示。
继续比赛按钮使用短文案。
```

## 14. 最小可行改版

如果只做一版尝试，建议先做这个最小版本：

```text
1. 顶部 sticky：比分、倒计时、继续比赛。
2. 简报压缩：原因、风险、最近 2 条。
3. 战术默认 compact：当前、备选、更多；助教提示打开后才标出推荐。
4. 换人默认 compact：轮换检查、完整名单入口；助教提示打开后才给一键推荐换人。
5. 底部或顶部显示最终方案摘要。
```

这一版不需要重写战术系统，也不需要重做换人系统。

它主要是：

```text
重排 DOM
调整 CSS
新增少量 UI 状态
补 AI snapshot
```

## 15. 验收标准

改版完成后，至少满足：

```text
1. 指挥台第一屏能看到暂停原因。
2. 指挥台第一屏能看到继续比赛按钮。
3. 指挥台第一屏能看到当前最终方案。
4. 默认不完整展示 12 个战术按钮。
5. 默认不完整展示全队换人名单。
6. 玩家能一键展开完整战术。
7. 玩家能一键展开完整阵容。
8. 助教提示关闭时不显示大块建议面板。
9. 助教提示关闭时不显示推荐标签、推荐摘要或一键推荐换人。
10. 助教提示打开时解释嵌入当前模块。
11. 点击多个战术后，最终方案摘要只显示最后草稿。
12. 点击继续后，直播只结算最终方案。
13. AI snapshot 能读取 compact / expanded / finalPlan / recommendations / firstScreenFits。
14. 推荐换人执行后，AI snapshot 能读取 confirmationVisible 和 confirmationText。
```

## 16. 玩家体验目标

改完后，玩家进入指挥台的感受应该从：

```text
好多东西，我要往下滑看看有什么。
```

变成：

```text
我知道为什么暂停，也知道现在先改什么。
```

更进一步，玩家应该感到：

```text
我可以快速做一个决定。
如果我想深挖，也有完整信息。
```

## 17. 最终原则

这次 UI 优化的核心不是减少系统深度。

核心是把深度变成层次：

```text
第一层：结论
第二层：操作
第三层：解释
第四层：完整数据
```

玩家默认看结论和操作。

需要时再看解释和完整数据。

AI 始终能读取全链路。
