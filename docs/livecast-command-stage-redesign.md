# 文字直播与指挥台阶段化重设计方案

## 1. 一句话结论

`指挥台`不应该是和`文字直播`并列的常驻 tab。

新的设计应当是：

```text
文字直播观察比赛
-> 玩家看到问题
-> 玩家主动叫暂停
-> 比赛进入指挥台布置阶段
-> 玩家调整战术 / 换人 / 阅读局势
-> 确认继续
-> 回到文字直播验证调整是否奏效
```

指挥台的定位要从“随时可打开的工具页”改成“暂停后的教练布置室”。它只能在合法布置窗口出现，不能让玩家在比赛进行中像切页面一样随便来回跳。

## 2. 当前体验问题

现在的结构大致是：

```text
比赛页
  文字直播 tab
  指挥台 tab
  实时数据 tab
```

这会带来几个体验问题。

### 2.1 指挥台太便宜

玩家随时能点进指挥台，就会把它理解成一个后台面板，而不是一次临场执教行为。

结果是：

- 叫暂停没有仪式感。
- 暂停次数没有资源价值。
- 战术调整像在切设置，而不是一次有成本、有后果的决策。
- 玩家不用先观察问题，就可以直接翻指挥台找答案。

这和“主教练看到场上出问题后叫暂停”的直觉相反。

### 2.2 文字直播和指挥台并列，削弱因果

玩家应该先通过文字直播感受到问题：

```text
对手连续冲击篮下
我方核心体力下降
联防被弱侧三分惩罚
对手一波 8-0
```

然后玩家产生反应：

```text
不行，要叫暂停。
```

现在 tab 并列后，玩家不需要这个心理过程。

他们可以直接进指挥台调整，导致体验变成：

```text
点指挥台
看推荐
点战术
回直播看结果
```

这不是“读比赛”，而是“查菜单”。

### 2.3 提示按钮绕过了暂停

现有的`该你出手了 / 进指挥台`提示，会把玩家从直播直接带到指挥台。

新的设计里，这个按钮不应该直接打开指挥台。它应该变成直播页上的问题信号：

```text
助教：对手这一波连续打到禁区，要不要叫暂停？
```

按钮行为也应从“进指挥台”改为“叫暂停”或“标记问题”，让玩家仍然经过暂停这个动作。

### 2.4 战术调整和换人没有被同一个窗口约束

现在已经有`subWindow`概念，换人被锁在暂停 / 节间窗口里，但战术仍然存在非窗口期直接提交的路径。

新的规则应当统一：

```text
比赛进行中：只能观察、叫暂停、看只读数据。
暂停 / 节间：才能进入指挥台，才能正式调整战术和换人。
继续比赛：提交最终方案，并在后续回合验证。
```

## 3. 新设计目标

### 3.1 玩家心理目标

让玩家的自然反应从：

```text
我去指挥台看看。
```

变成：

```text
场上不对劲，我得叫暂停。
```

这句话是整个 redesign 的核心。

### 3.2 系统目标

新的系统需要保证：

- `文字直播`是比赛进行时的主视角。
- `指挥台`只在布置窗口出现。
- `叫暂停`是从直播进入指挥台的主要入口。
- `战术`和`换人`都在同一个布置窗口里提交。
- 指挥台关闭后，必须回到文字直播。
- 直播要解释“刚才那次布置有没有奏效”。
- AI 验证可以证明指挥台没有在非法阶段出现。

### 3.3 玩法目标

暂停要成为真正的战术资源：

```text
不叫暂停：继续忍受场上问题，但保留暂停次数。
叫暂停：消耗资源，换来完整布置权和止血机会。
```

这会让玩家的决策更像篮球比赛里的主教练，而不是一个随时能暂停世界的后台管理员。

## 4. 新核心循环

### 4.1 主循环

```text
1. 文字直播连续播出比赛事件
2. 系统通过直播和局势条暴露问题
3. 玩家判断是否值得叫暂停
4. 玩家叫暂停
5. 进入指挥台布置阶段
6. 玩家调整战术 / 换人 / 查看助教提示
7. 玩家确认继续
8. 回到文字直播
9. 后续 3-5 回合给出战术反馈
10. 对手可能反制，新的问题再出现
```

### 4.2 关键体验节奏

新的节奏不是：

```text
直播 tab <-> 指挥台 tab
```

而是：

```text
直播观察期 -> 暂停布置期 -> 直播验证期
```

这三个阶段必须有清晰边界。

### 4.3 玩家动机链

每一次进指挥台，都应该回答一个明确问题：

```text
我为什么叫这个暂停？
我想解决什么问题？
我要用什么战术解决？
当前阵容能不能执行？
继续比赛后，我怎么知道它奏效了？
```

如果指挥台是随时可进的 tab，这条动机链就会断掉。

## 5. 合法入口规则

指挥台只允许在以下窗口出现。

| 入口 | 是否打开指挥台 | 是否消耗暂停 | 说明 |
| --- | --- | --- | --- |
| 我方主动叫暂停 | 是 | 是 | 核心入口 |
| 节间休息 | 是 | 否 | 自然布置窗口 |
| 新手引导指定步骤 | 是 | 可脚本化 | 必须仍然教玩家“先观察，再暂停” |
| 关键球系统强制布置 | 可选 | 视规则 | 仅限最后一攻等特殊场景 |
| 对手叫暂停 | 默认否 | 否 | 只在直播里展示对手暂停，不给我方完整指挥台 |
| 比赛进行中点击指挥台 | 不存在 | 不存在 | UI 上不再提供这个入口 |
| 助教提示 | 不直接打开 | 不直接消耗 | 只提示问题，引导玩家叫暂停 |

### 5.1 对手暂停为什么默认不进指挥台

从真实篮球逻辑看，对手暂停时我方当然也能布置。

但从游戏体验看，如果每次对手暂停都免费打开完整指挥台，会削弱玩家主动叫暂停的价值。

建议第一版规则：

```text
对手暂停只在文字直播中呈现。
我方可以得到一句“对手叫暂停，比赛节奏被打断”的局势反馈。
不自动进入完整指挥台。
```

未来如果要扩展，可以做一个较弱的“场边提醒”：

```text
对手暂停期间，你可以查看局势，但不能换人或正式改战术。
```

但第一版不建议加，避免规则变复杂。

## 6. 页面结构重设计

### 6.1 取消并列 tab

当前：

```text
文字直播 tab
指挥台 tab
实时数据 tab
```

改为：

```text
比赛直播页
  文字直播流
  局势条
  暂停按钮
  简短数据入口

暂停指挥页
  暂停原因
  最近问题回放
  战术布置
  换人布置
  助教提示开关
  确认继续
```

### 6.2 文字直播页

文字直播页是比赛进行时唯一主界面。

它应该包含：

- 顶部比分、节次、时间、球权。
- 当前局势条。
- 文字直播流。
- 暂停按钮。
- 暂停次数。
- 速度控制。
- 可选的只读数据入口。

它不应该包含：

- 指挥台 tab。
- 战术选择按钮。
- 换人按钮。
- 默认推荐战术。
- 直接进入指挥台的助教按钮。

### 6.3 直播页上的问题信号

直播页可以提示问题，但不要替玩家做完整解法。

推荐文案方向：

```text
对手连续三回合冲到篮下，禁区保护正在吃紧。
```

```text
布伦森体力明显下降，推进节奏开始变慢。
```

```text
马刺这一波 8-0，场边已经有叫暂停的压力。
```

这些都是“观察信号”，不是“战术答案”。

### 6.4 暂停按钮

暂停按钮应成为直播页上的主要操作。

默认状态：

```text
叫暂停
```

当系统检测到问题时，可以强化按钮状态：

```text
叫暂停止血
```

```text
暂停布置
```

但不应该出现：

```text
进指挥台
```

因为“进指挥台”是结果，“叫暂停”才是玩家行为。

### 6.5 数据入口如何处理

`实时数据`不应该再和`文字直播 / 指挥台`并列成 tab。

建议改为：

```text
直播页：一个只读数据抽屉 / 小按钮
指挥台页：战术相关数据摘要
赛后页：完整 box score
```

数据可以随时看，但不能成为去指挥台的侧门。

## 7. 指挥台页面重设计

指挥台是暂停期间出现的完整布置页。

### 7.1 顶部必须说明“为什么进来”

指挥台顶部不要只是标题。

它应该告诉玩家：

```text
暂停原因：对手打出 8-0，连续两次冲击篮下得手。
```

或者：

```text
节间布置：第二节开始前，你可以调整阵容和攻防策略。
```

这个信息来自暂停前的`PossessionContext`和局势检测。

### 7.2 指挥台结构

建议结构：

```text
指挥台

1. 暂停原因 / 局势摘要
2. 最近 3-5 回合问题回放
3. 当前阵容画像
4. 进攻战术
5. 防守战术
6. 换人
7. 助教提示
8. 确认继续
```

### 7.3 指挥台不播新直播

进入指挥台后，比赛已经暂停。

所以指挥台不应该继续滚动直播。

可以显示“暂停前回放”，但那是静态摘要：

```text
最近问题：
Q2 8:14 对手突破上篮命中
Q2 7:52 我方外线三分打铁
Q2 7:35 对手二次进攻得手
```

它用于帮助玩家复盘，而不是继续比赛。

### 7.4 战术选择是草稿，确认继续时提交

暂停期间玩家可以反复点战术，但这些都只是草稿。

只有点击`继续比赛`时，才正式提交最终方案。

```text
暂停中：
  点击强打内线 -> 草稿
  点击巨星单打 -> 草稿覆盖
  点击团队传导 -> 草稿覆盖

继续比赛：
  只提交团队传导
```

这可以避免之前出现的“暂停期间点过的战术全都被直播结算”的问题。

### 7.5 换人和战术必须互相解释

换人不只是“谁体力低”。

指挥台里换人应该回答：

```text
这次换人服务于什么战术？
```

示例：

```text
你选择外线火力，但当前场上只有 1 个稳定空间点。
建议换上沙梅特，增加弱侧投射。
```

```text
你选择收缩护框，但唐斯护框不足。
建议上米切尔-罗宾逊，提高禁区保护。
```

### 7.6 助教提示放在指挥台内部

比赛进行时，助教只提示“问题”。

暂停进入指挥台后，助教才可以提示“方案”。

也就是：

```text
直播中：发现问题
指挥台：分析解法
```

这样既保留玩家读比赛的责任，也保留新手帮助。

### 7.7 继续比赛按钮

指挥台底部只有一个明确出口：

```text
确认布置，继续比赛
```

如果有倒计时，按钮文案可以是：

```text
继续比赛（12s）
```

点击后：

- 提交最终战术草稿。
- 提交最终换人。
- 创建`commandSessionId`、`coachActionId`、`adjustmentId`。
- 回到文字直播。
- 播放“暂停结束，比赛继续”。
- 后续回合开始验证调整效果。

## 8. 状态机设计

### 8.1 用阶段替代自由 view

当前状态：

```js
S.view = "feed" | "box" | "cmd";
S.subWindow = true | false;
```

建议改为更明确的阶段：

```js
S.phase = "live" | "command" | "resume_feedback" | "postgame";
```

同时保留更具体的窗口来源：

```js
S.commandSession = {
  id: "cmd_001",
  reason: "player_timeout",
  openedAt: { quarter: 2, clock: 456 },
  problemIds: ["problem.opp_run", "problem.rim_pressure"],
  sourceContextIds: ["ctx_041", "ctx_042", "ctx_043"],
  draftScheme: {
    off: "motion",
    def: "paint"
  },
  draftSubs: [
    { out: "shamet", in: "robinson" }
  ],
  committed: false
};
```

### 8.2 阶段流转

```text
live
  -> player_timeout
  -> command
  -> commit_command
  -> resume_feedback
  -> live
```

节间：

```text
live
  -> quarter_break
  -> command
  -> commit_command
  -> live
```

赛后：

```text
live
  -> postgame
```

### 8.3 不变量

必须保证以下不变量：

```text
S.phase !== "command" 时，指挥台不可见、不可点击。
S.phase === "live" 时，战术按钮不存在或 disabled。
S.phase === "live" 时，换人按钮不存在或 disabled。
S.phase === "command" 时，比赛计时停止。
S.phase === "command" 时，文字直播不新增比赛回合。
S.phase 从 command 离开时，只提交最终草稿。
```

这些不变量要进入 AI 验证。

## 9. 现有系统改造点

### 9.1 `live.html`

需要改：

- 移除视觉上的 tab 栏。
- `feed`作为直播页主体。
- `cmd-wrap`升级为阶段页面，而不是 tab 内容。
- `box-wrap`改为只读数据抽屉或赛后数据页。
- `coach-prompt`文案从“进指挥台”改成“叫暂停 / 场边提醒”。

建议新增或调整的测试标识：

```text
live-screen
live-feed
live-timeout-button
live-data-drawer
command-screen
command-reason
command-recent-possessions
command-offense-section
command-defense-section
command-lineup-section
command-confirm
```

### 9.2 `state.mjs`

需要改：

```js
view: "feed"
```

替换为：

```js
phase: "live",
commandSession: null,
dataDrawerOpen: false
```

`subWindow`可以暂时保留作为兼容字段，但最终建议被`phase === "command"`替代。

### 9.3 `live-sim.mjs`

重点改造函数：

| 当前函数 / 逻辑 | 新方向 |
| --- | --- |
| `setView(v)` | 改为`setPhase(phase, reason)` |
| tab onclick | 删除指挥台 tab，保留数据抽屉入口 |
| `openSubWindow()` | 改名为`openCommandSession()` |
| `closeSubWindow()` | 改名为`commitCommandSession()` |
| `openCoachPrompt()` | 不再直接`setView("cmd")`，改为引导暂停 |
| `setMyScheme()` | 非 command 阶段直接 return 或显示“需要暂停布置” |
| `renderCmd()` | 只在 command 阶段渲染完整内容 |
| `renderCoachPrompt()` | 提示问题，不提示直接进指挥台 |
| `togglePause()` | 成为直播到指挥台的主入口 |

### 9.4 战术提交规则

当前逻辑里非暂停期可以：

```js
commitMySchemeChange(kind, key, prev, "scheme-change");
```

新规则：

```text
比赛进行中不能正式改战术。
战术变化必须来自 commandSession commit。
```

如果未来想保留“场边手势”这种轻量操作，也应该做成独立系统，而不是打开完整指挥台。

### 9.5 换人规则

换人继续锁定在布置窗口。

但换人 UI 只在`phase === "command"`出现，不再在比赛进行中展示一堆 locked 球员卡。

比赛进行中如果要提示体力问题，应在直播页以文字信号呈现：

```text
阿奴诺比连续追防，体力已经明显吃紧。
```

而不是让玩家看到一个不能操作的换人面板。

### 9.6 助教 / 新手引导

新手引导顺序要改成：

```text
1. 看文字直播和局势条
2. 等待问题出现
3. 点击叫暂停
4. 指挥台出现
5. 选择战术
6. 完成换人
7. 确认继续
8. 回到直播看反馈
```

不再教学“点击指挥台 tab”。

### 9.7 `ai-verify.mjs`

需要扩展快照：

```js
game: {
  phase,
  commandOpen,
  commandReason,
  commandSessionId,
  commandCommitted,
  dataDrawerOpen
}
```

需要新增断言：

```text
command.hidden_during_live
command.visible_only_during_command_phase
command.requires_timeout_or_break
live.no_command_tab
live.timeout_button_present
prompt.does_not_open_command_directly
scheme.locked_outside_command
sub.locked_outside_command
command.commit_returns_to_live
command.commit_only_final_scheme
```

## 10. 文字直播的职责变化

文字直播不再只是播结果。

它要承担三个职责：

### 10.1 暴露问题

例：

```text
马刺连续两个回合打到篮下，尼克斯禁区保护正在被考验。
```

### 10.2 促成暂停动机

例：

```text
这一波已经来到 8-0，场边有必要把比赛按下来。
```

### 10.3 验证布置效果

暂停回来后 3-5 回合，直播要主动回应刚才布置：

```text
暂停后尼克斯改打团队传导，球终于从强侧转到了弱侧。
```

```text
这次换上罗宾逊开始起作用，文班亚马这一球没有再轻松到篮下。
```

```text
思路是对的，但外线投射还是没进，暂停效果暂时没有兑现。
```

### 10.4 不要过度教学

直播可以告诉玩家“出了什么问题”，但不要默认告诉“标准答案”。

战术推荐应该放在指挥台里的`助教提示`按钮之后。

## 11. 指挥台与战术系统的关系

新关系：

```text
指挥台不是战术系统本身。
指挥台是战术系统的提交场景。
```

战术系统仍然负责：

- 进攻战术。
- 防守战术。
- 战术克制。
- 阵容适配。
- 对手反制。
- 调整窗口追踪。

但玩家能正式改战术的时间，被指挥台阶段控制。

这会让战术系统更有重量：

```text
我不是每回合随便改。
我是消耗暂停，做出一次布置，然后承担后果。
```

## 12. 指挥台与换人系统的关系

换人系统应当完全归入指挥台阶段。

它不再是一个随时可查看但大部分时候 locked 的面板。

新的换人体验：

```text
直播中：看到体力 / 对位问题
暂停后：在指挥台里调整阵容
继续后：直播反馈换人效果
```

### 12.1 换人理由要被记录

每次换人要落 trace：

```js
{
  commandSessionId: "cmd_001",
  coachActionId: "ca_012",
  subActionId: "sub_004",
  out: "towns",
  in: "robinson",
  intendedFix: "rim_protection",
  linkedScheme: "paint",
  sourceProblemIds: ["problem.rim_pressure"]
}
```

这样直播才能说清楚：

```text
暂停后换上罗宾逊，就是为了处理刚才连续丢禁区的问题。
```

## 13. 指挥台与暂停资源的关系

暂停应该有三层价值：

### 13.1 止血

叫暂停立即降低对手一波流、情绪和主场声浪影响。

### 13.2 布置

叫暂停打开完整指挥台，允许战术和换人一起调整。

### 13.3 追踪

叫暂停创建一个可追踪的调整窗口。

```text
这次暂停后的 3-5 回合，系统会评估：
战术有没有执行？
换人有没有解决问题？
对手有没有反制？
```

## 14. 对手 AI 适配

对手 AI 也要读新的指挥台结果。

玩家从指挥台提交后：

```text
commandSession -> adjustmentWindow -> opponentAdaptation
```

对手可以在后续几回合观察：

- 玩家是否连续打外线。
- 玩家是否换上射手。
- 玩家是否开始收缩护框。
- 玩家是否用包夹核心。

然后对手才反制。

这会形成新的循环：

```text
我方叫暂停布置
-> 暂停后奏效
-> 对手识别
-> 对手调整
-> 新问题出现
-> 我方决定是否再叫暂停
```

## 15. UI 行为细则

### 15.1 比赛进行中

允许：

- 看文字直播。
- 看比分、时间、暂停数。
- 调速度。
- 打开只读数据抽屉。
- 叫暂停。

不允许：

- 进入指挥台。
- 改战术。
- 换人。
- 查看默认战术推荐。

### 15.2 暂停 / 节间

允许：

- 查看暂停原因。
- 查看最近问题回放。
- 改进攻战术草稿。
- 改防守战术草稿。
- 换人草稿。
- 打开助教提示。
- 确认继续。

不允许：

- 继续滚动比赛直播。
- 切回直播页绕过布置阶段。
- 多次点击产生多个正式战术提交。

### 15.3 暂停结束

系统必须：

- 只提交最终草稿。
- 隐藏指挥台。
- 回到文字直播。
- 播放暂停结束信息。
- 开启调整验证窗口。

## 16. AI 可验证设计

这次改造必须继续满足“AI 原生可验证”。

### 16.1 快照字段

建议新增：

```js
{
  game: {
    phase: "live",
    commandOpen: false,
    commandReason: "",
    commandSessionId: "",
    canOpenCommand: false,
    canCallTimeout: true
  },
  command: {
    active: false,
    reason: "",
    draftOff: "",
    draftDef: "",
    draftSubs: [],
    sourceProblemIds: [],
    sourceContextIds: [],
    committed: false
  }
}
```

### 16.2 DOM 断言

AI 需要能验证：

```text
直播阶段看不到指挥台。
直播阶段没有指挥台 tab。
直播阶段点击助教提示不会打开指挥台。
点击叫暂停后进入指挥台。
指挥台阶段比赛停止。
指挥台阶段可以改战术草稿。
点击继续后指挥台消失。
继续后回到文字直播。
继续后只提交最终战术。
```

### 16.3 Trace 断言

AI 需要能追溯：

```text
问题来自哪些回合。
玩家为什么叫暂停。
暂停打开了哪个 commandSession。
玩家最终提交了什么战术和换人。
后续哪些直播行在反馈这个 commandSession。
这次调整最终成功还是失败。
```

当前实现需要额外追踪一次`command.commit`：

```text
command.commit.summaryRows === 1
command.commit.draftSpamRows === 0
command.commit.summaryTracePresent === true
```

含义是：暂停内点过的战术和换人都是草稿，点击继续后只生成一条`最终布置`直播摘要；这条摘要带有`coachActionId`、`adjustmentId`、`livecastId`，后续 AI debug 可以从反馈行一路追回这次指挥台提交。

## 17. 分阶段执行方案

### Phase 1：交互入口改造

目标：先消除“并列 tab”的体验问题。

改动：

- 去掉指挥台 tab。
- 直播页保留叫暂停按钮。
- `coach-prompt`不再直接打开指挥台。
- `openCoachPrompt()`改为引导 / 执行暂停。
- 非暂停期不能进入指挥台。
- 非暂停期不能改战术。

验收：

```text
比赛进行中看不到指挥台入口。
只有叫暂停后才出现指挥台。
继续比赛后自动回到文字直播。
```

### Phase 2：指挥台页面重排

目标：让指挥台看起来就是“暂停布置室”。

改动：

- 指挥台顶部新增暂停原因。
- 新增最近 3-5 回合问题摘要。
- 战术、换人、助教提示重新排序。
- 加明确的“确认布置，继续比赛”按钮。
- 数据摘要服务于战术，不再像单独 tab。

验收：

```text
玩家一进指挥台就知道为什么暂停。
玩家能围绕同一个问题改战术和换人。
```

### Phase 3：状态机和 AI 验证

目标：让规则从 UI 约定变成系统约束。

改动：

- `S.view`升级为`S.phase`。
- 新增`commandSession`。
- 新增 AI 快照字段和断言。
- 文档更新新人验证流程。

验收：

```text
AI 可以断言指挥台只在 command phase 可见。
AI 可以追踪一次暂停从问题到布置再到直播反馈的完整链路。
```

### Phase 4：直播反馈强化

目标：让暂停后的结果更明显。

改动：

- 直播在暂停后 3-5 回合主动反馈调整。
- 失败时说明是战术错、阵容不适配、手感问题还是对手反制。
- 对手 AI 根据玩家指挥台提交结果做延迟反制。

验收：

```text
玩家能从直播里感受到“我刚才那次暂停到底有没有用”。
```

## 18. 验收标准

最终版本至少满足以下标准：

```text
1. 比赛进行中没有指挥台 tab。
2. 比赛进行中不能直接打开指挥台。
3. 直播页上的问题提示不会直接跳指挥台。
4. 玩家点击叫暂停后才进入指挥台。
5. 指挥台进入时比赛停止。
6. 指挥台顶部说明暂停原因。
7. 暂停期间可反复试战术，但只提交最终方案。
8. 暂停期间可换人，换人和战术互相解释。
9. 点击继续后指挥台关闭，回到文字直播。
10. 暂停后直播反馈本次布置是否奏效。
11. AI 验证能检查上述状态。
```

## 19. 资源缺口

### 19.1 设计资源

缺：

- 新的直播页布局稿。
- 新的指挥台页布局稿。
- 暂停原因卡片样式。
- 最近问题回放组件样式。
- 只读数据抽屉样式。

可以先用现有 UI 改，不一定需要完整视觉稿。

### 19.2 文案资源

缺：

- 直播中的问题信号文案。
- 暂停原因文案。
- 暂停后验证文案。
- 失败归因文案。
- 对手反制文案。

这些文案会直接决定玩家能不能读懂“为什么要叫暂停”。

### 19.3 数据资源

已有：

- 回合 context。
- 战术 trace。
- 阵容 profile。
- adjustment window。

需要补强：

- 问题识别标签：`problem.opp_run`、`problem.rim_pressure`、`problem.fatigue`等。
- `commandSessionId`。
- 暂停原因和最近问题回放之间的映射。

### 19.4 验证资源

需要新增：

- 指挥台阶段断言。
- 非法入口断言。
- 草稿提交断言。
- 暂停后反馈断言。

## 20. 最终设计原则

这次 redesign 的原则可以压缩成四句话：

```text
文字直播负责让玩家看见问题。
暂停负责让玩家付出决策成本。
指挥台负责让玩家解决问题。
后续直播负责证明玩家解决得好不好。
```

只要这个顺序成立，战术、换人、直播才会真正环环相扣。
